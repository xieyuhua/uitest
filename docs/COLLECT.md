## 1. 它能做什么 / 不做什么

| 做 | 说明 |
|---|---|
| 录下真实请求 | 插件或内置浏览器旁路录制：方法、URL、状态、请求头、请求体、响应体（默认截断 256KB） |
| 筛选与裁剪 | 按方法/类型/状态/关键字/正则筛，逐条或批量删掉不想要的接口 |
| 定时抓取 | 每 N 秒 / 每天 HH:MM / 每周几，带随机抖动；单任务串行，不叠加 |
| 自动翻页 | 页码 / 偏移 / 游标 / 请求体内参数，五种停止条件 + 打转检测 + 跨页去重 |
| 落库 | SQLite、MySQL、PostgreSQL、Excel `.xlsx`、JSON `.json`、JSONL；后三种可在控制台下载 |
| 先看再写 | 「试抓预览」不写库看列与前几行；「测试落库」只验连接 |

**不做**：代理池、UA/指纹伪造、验证码或 WAF 绕过、多账号轮询——这类对抗风控的事不在范围内。
限速、抖动、退避、熔断都是**刻意**的限制：保护对方服务，也保护你自己不被封。

## 2. 5 分钟跑通一条

```powershell
go build -o uitest-server.exe . && .\uitest-server.exe     # 或 .\start.ps1
```

1. 打开 <http://127.0.0.1:8490> → 顶部「接口采集」；
2. 起始页填 `http://127.0.0.1:8490/demo/api-center.html` → 「开始录制」（会开一个内置浏览器标签页）；
3. 在**那个标签页**里点两下「下一页」（让 URL 里出现 `page=2`）→ 回控制台「停止录制」；
4. 进「录制结果」→ 勾上 `GET /demo/api/goods` →「下一步：配置采集任务」；
5. 定时选「每 1 小时」，落库选 **Excel 表格**，表名 `demo_goods` → 创建 → 「立即运行」；
6. 运行详情显示「写入 23 行」，回首页「产出文件」下载 `.xlsx`。

示例接口固定 23 条、每页 3 条，所以自动翻页会走 8 页后停在「总数 23 条已抓完」。

## 3. 录制：两种方式

| 方式 | 怎么用 | 适合 | 抓取原理 |
|---|---|---|---|
| **浏览器插件**（推荐） | 装 `extension/`，弹窗勾着「同时录制接口请求」，在你自己的浏览器里正常操作 | 已登录的系统、走公司代理/固定 IP、不想再登录一遍 | `net-hook.js` 注入页面主世界，包 `fetch`/`XHR` 记录后批量上报 |
| **内置浏览器** | 「录制接口」卡片填起始页 → 开始录制，服务端开标签页旁路录 | 想干净隔离，或不想动自己的浏览器 | CDP `Network` 域旁路监听 |

两种方式录到的结果完全一样，进同一份「录制结果」；后续筛选、删除、建任务流程也一样。

**插件方式的细节**：

- 弹窗里能看到「已录接口 N 条」，页面右下角浮层显示 `● 录制中 · N 步 · M 接口`；
- 停止录制后**自动打开「录制结果」页**（弹窗里「停止录制后自动打开」可关），也可点「去勾选接口 → 建采集任务」；
- 自动跳过 `服务端地址/api/` 前缀（不录平台自己）与 `chrome-extension://`；
- 抓不到的：二进制响应（图片/文件）、`EventSource`/`WebSocket` 流数据；
- 页面在装/重载插件之前就打开的话，刷新一次即可；
- 插件崩了会话会一直「录制中」——30 分钟无上报自动判停，也可在列表里「丢弃」。

### 3.1 登录态

**录制即登录**：你在录制时正常登录，请求自然带着 Cookie/Token 被录下来。建任务时会话默认复用：

| 模式 | 适用 | 说明 |
|---|---|---|
| `browser`（默认） | 大多数后台系统 | 运行时从内置浏览器导出 Cookie，30 分钟内复用；浏览器没启动会自动拉起 |
| `cookie` | 无桌面的 Linux 服务器 | 手工粘贴 `a=1; b=2`，适合服务账号长期 Token |
| `none` | 公开接口 | 不带登录态 |

> 取 Cookie：登录后 F12 → Network → 任意请求 → 复制请求头 `Cookie` 整行。
> **Cookie 明文存在 `data/uitest.json`**，别提交到代码库。
> 用插件录、又打算在服务器上跑定时任务的，建议直接用 `cookie` 模式。

### 3.2 录制小技巧

- 想抓"翻页"接口就真的翻两页——这样 `page` 参数会被识别出来；
- 列表接口自带"空结果页"也不用管，抓到空页会自动停；
- 页面用了强缓存看不到请求时，勾「含页面文档」或换个入口重新进；
- 内置浏览器方式最多同时保留 5 个录制会话，旧的自动关闭。

## 4. 筛选与裁剪

「录制结果」页（`GET /api/collect/captures/{id}`）的筛选全部走服务端：

| 筛选 | 作用 |
|---|---|
| 关键字 | 匹配 URL / 路径 / 主机 |
| 方法 | GET / POST / PUT / PATCH / DELETE |
| 类型 | XHR / Fetch / Document |
| 状态 | 2xx / 4xx / 5xx（API 也可用 `min_status` / `max_status`） |
| 只看 | `JSON 响应`（推荐）/ `有响应体` |
| include 正则 | 只保留 URL 命中的，如 `/api/(goods\|orders)` |
| exclude 正则 | 排除噪声，如 `heartbeat\|log\|collect\|sentry` |

典型用法：`include=/api/` + `exclude=heartbeat|log` + `只看=JSON 响应`，一屏就干净了。

点某行「查看」看响应体结构：自动识别**记录数组在哪**（如 `data.list`）、推测字段映射、给出前几行预览——
这份预览就是后面入库的列。

### 4.1 删掉不想要的接口

| 操作 | 怎么做 | 效果 |
|---|---|---|
| 删单条 | 该行右侧「删除」 | 只从这次录制结果移除这一条 |
| 批量删 | 勾选几行 → 底部「删除选中（N）」 | 一次移除多条 |
| 按条件删 | 先筛出噪声（如 `exclude=heartbeat`）→「全选当前筛选结果」→「删除选中」 | 批量清理噪声 |
| 清空这次录制 | 右上「删除这次录制」 | 整个会话丢弃（任务与已入库数据不受影响） |

删除是真删：不会出现在列表、筛选统计、建任务的可选范围里；插件即使重发同一条也会被忽略（按请求 id 幂等）。
两类来源都支持（插件录制直接摘数据，内置浏览器录制走"屏蔽名单"）。

## 5. 建采集任务

勾选接口 →「下一步：配置采集任务」→ 四段配置（定时 / 限速 / 落库 / 会话）。

任务详情里**每个接口是一个可折叠的块**：点标题左侧 `▸` 展开、`▾` 收起，
标题行显示摘要（`GET · 页码分页 · 3 字段`）。折叠只影响显示，不会丢未保存的修改。

### 5.1 定时计划

| 模式 | 参数 | 说明 |
|---|---|---|
| 固定间隔 | 间隔（秒）+ 触发抖动 % | 每 N 秒一次；抖动在 ±p% 内随机，避免整点扎堆 |
| 每天定时 | 每日时刻（`09:00,21:30`）+ 每周几（`1,3,5`，空=每天） | 到点触发，带 0–5 分钟抖动 |
| 仅手动 | — | 只在你点「立即运行」时跑 |

服务端规则：

- `next_run_at` 由服务端维护，列表直接显示；
- **重启不补跑**错过的点，顺延到下一个时间（避免一开机打一串请求）；
- 上一轮没跑完时下一轮直接跳过（不叠加）；
- 调度粒度 10 秒，「每天 09:00」实际在 09:00:00–09:00:10 之间触发。

### 5.2 礼貌限速与容错

| 参数 | 默认 | 作用 |
|---|---|---|
| `min_interval_ms` | 1000 | 相邻请求最小间隔（低于 200 会被拉回默认值） |
| `jitter_percent` | 30 | 间隔随机抖动 ±p% |
| `timeout_ms` | 20000 | 单请求超时 |
| `retries` | 2 | 失败重试（指数退避；429/503/5xx/网络错误才重试） |
| `backoff_ms` | 1500 | 退避基数 |
| `max_fail_streak` | 3 | 连续失败几个接口就熔断本次运行 |
| `max_pages_cap` | 50 | **分页默认上限**：只在接口没填「最多页数」时生效；接口填了就以接口为准（硬顶 2000） |

> 想抓 500 页？直接把接口的「最多页数」填 500 即可 —— 这个值不会被任务的默认上限压回去，
> 只有超过 2000 才会被夹到 2000。填 `0`/留空才回落到任务的「分页默认上限」。

遇到这些状态**立刻停手**，原因写进运行详情：

| 状态 | 含义 | 处理 |
|---|---|---|
| `401` / `403` | 会话失效或被拒 | 重新登录再录一遍，或更新 Cookie |
| `429` | 被限流 | 停后续接口，调大间隔重试 |
| 其它 4xx | 参数/路径不对 | 不重试，直接报错 |

### 5.3 落库

| 驱动 | 产物 | 说明 |
|---|---|---|
| `sqlite`（默认） | `data/harvest/harvest.db` | 零依赖，可填相对/绝对路径 |
| `xlsx` | `data/harvest/<表名>.xlsx` | **Excel 表格**，可下载；表头加粗 + 冻结首行，数字按数字存 |
| `json` | `data/harvest/<表名>.json` | **JSON 文件**（对象数组），可下载 |
| `jsonl` | `data/harvest/<表名>.jsonl` | 追加写，pandas / DuckDB / jq 直接读 |
| `mysql` | 数据库表 | DSN：`root:pass@tcp(127.0.0.1:3306)/test?charset=utf8mb4&parseTime=true` |
| `postgres` | 数据库表 | DSN：`postgres://user:pass@127.0.0.1:5432/test?sslmode=disable` |

都是纯 Go 驱动，不需要 CGO 或本地客户端库。行为：

- **SQL 类**：表不存在自动 `CREATE TABLE`（整数→`INTEGER`、小数→`REAL`、文本→`TEXT`、对象/数组→JSON 文本）；
  响应多出字段自动 `ALTER TABLE ADD COLUMN`；`upsert` 按「去重键列」建唯一索引并覆盖；
- **文件类**：文件不存在自动创建；`xlsx` / `json` 每次**整份重写**（表头随字段增长），
  `upsert` 同样按去重键覆盖，行数不会随运行次数翻倍；`jsonl` 只追加；
- 每行自动带 `_fetched_at`（采集时刻），方便排查与去重。

> 表名建议全小写；Excel/JSON 的文件名就是表名，`/` `\` 等字符会自动替换成 `_`。
> MySQL 记得 `charset=utf8mb4`，否则中文变问号。

### 5.4 会话

见 [3.1](#31-登录态)。`browser` 模式要求这台机器能起浏览器；
纯服务器部署用 `cookie` 模式，或把录制放在有桌面的机器上、任务共用同一份 `data/`。

## 6. 记录路径 / 字段映射 / 变量

### 6.1 记录路径（`records_path`）

响应里"记录数组"的位置，点「查看」通常自动填好：

```
{"code":0,"data":{"total":6,"list":[{...}]}}   → data.list
[{...},{...}]                                  → 留空（响应本身就是数组）
{"data":{"item":{...}}}                        → 自动按单条记录处理
```

留空时服务端自动找"最像列表"的数组（元素是对象、元素最多、层级最浅）。

### 6.2 字段映射（列名 ← 路径）

| 路径写法 | 含义 |
|---|---|
| `id` / `name` | 顶层字段 |
| `owner.name` | 嵌套对象 |
| `list[0].price` | 数组下标 |
| `@now` `@datetime` | 采集时刻 |
| `@date` / `@timestamp` | 采集日期 / 时间戳 |
| `@url` / `@endpoint` / `@page` | 当前接口 URL / 接口名 / 页码 |

列名允许中文，但建议英文小写 + 下划线，跨库更稳。
没配字段时运行会按响应自动识别，并在日志里提示"建议保存字段映射"。

### 6.3 URL / 请求体里的变量

```
https://api.example.com/goods?page={{page}}&day={{date}}
```

| 变量 | 值 |
|---|---|
| `{{page}}` | 当前页码（分页时自动递增） |
| `{{now}}` `{{date}}` `{{datetime}}` `{{timestamp}}` | 本地时间 / 日期 / 秒级时间戳 |
| `{{uuid}}` | 随机 UUID |
| `{{host}}` | 接口所在主机 |
| `{{env:NAME}}` | 读环境变量（**密钥放环境里，别写进任务**） |

## 7. 分页抓取

列表接口几乎都分页；只抓第一页 = 只拿一页，所以这块决定"能不能抓全"。

### 7.1 三种翻页方式

| 方式 | 长什么样 | 典型场景 |
|---|---|---|
| **页码** | `?page=1` / `?pageNo=2` / `?current=3` | 后台管理列表 |
| **偏移** | `?offset=0&limit=20` → `offset=20,40…` | 开放 API、ES 风格 |
| **游标** | 响应给 `next_cursor`，下次带上 | 深分页、时间线、Feed |

参数放 **URL** 或 **请求体（POST JSON）** 都支持（「参数位置」选 URL 参数 / 请求体 JSON）。

### 7.2 自动识别（什么都不填就行）

录制时那条请求 + 响应样本会被用来推断：翻页参数名、每页条数、总数字段
（`data.total` / `totalCount` / `recordsTotal`…）、`has_more` 类结束标志、游标路径。
建任务时已填好，分页框上方显示总结：

```
分页  页码分页：page，每页 3 条，总数取自 data.total，最多 9 页     [自动识别分页]
```

不准就点「自动识别分页」重算，或手工改：

| 字段 | 说明 |
|---|---|
| 翻页方式 | 自动 / 页码 / 偏移 / 游标 / 不分页 |
| 参数名 | `page` / `offset` / `cursor`（按你的接口写） |
| 参数位置 | URL 参数 或 请求体 JSON |
| 每页条数 | 判断"最后一页"与偏移步长 |
| 最多页数 | 安全阀。**填了就以你填的为准**（硬顶 2000 页）；留空则用任务的「分页默认上限」（默认 50） |
| 起始值 | 页码从 1 还是 0 开始 |
| 总数字段 | 如 `data.total`（有它就能精确停） |
| 结束标志 | 如 `data.has_more`（false 就停） |
| 游标字段 | 如 `data.next_cursor` |
| 短页即止 | 返回条数 < 每页条数 → 认为最后一页 |

### 7.3 五个停止条件（满足任一即停）

1. 本页返回 **0 条**；
2. 本页条数 **< 每页条数**（短页即止，可关）；
3. 响应里的 **总数已抓完**（`ceil(total / page_size)` 页）；
4. **`has_more = false`**，或游标为空/不再变化；
5. 达到 **最多页数**（你自己填的值，硬顶 2000；留空时用任务的「分页默认上限」，默认 50）。

外加两条安全行为：

- **原地打转检测**：连续两页内容完全一致（典型原因：接口根本不吃 `page`）→ 立刻停，
  运行详情写「连续两页数据完全相同，判定接口忽略了分页参数」，不会傻跑 50 页；
- **跨页去重**：同一行在多页重复出现时跳过，运行详情显示「去重 -N」。

运行详情里的样子：

```
▶ 采集接口 GET https://example.com/api/goods?page=1&size=3
分页策略：页码分页：page（从 1 起，最多 9 页，每页约 3 条，总数取自 data.total）
第 1 页：3 条（累计 3 条）
...
第 8 页：2 条（累计 23 条）
停止翻页：总数 23 条已抓完（每页 3 条）
```

### 7.4 常见分页坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 只抓到第一页 | 参数名猜错（接口用 `pageNo`，配成了 `page`） | 在浏览器翻一页看 URL 真实参数名，或改「参数名」 |
| 抓了 50 页全是同一批 | 接口不吃分页（前端本地分页 / 一次返全量） | 改成 `不分页`；系统也会自动停并提示 |
| 第 2 页起就没数据 | 页码从 0 开始，或需同时传 `page_size` | 把「起始值」改成 0；检查每页条数 |
| 游标模式只抓一页 | 游标字段路径写错 | 填完整路径，如 `data.next_cursor` |
| POST 接口翻不动 | 参数在请求体里却写进了 URL | 「参数位置」改 `请求体 JSON` |
| 总数对不上（少几条） | 抓取期间数据在变 | 正常；用 `upsert` + 唯一键，跑两次对齐 |

## 8. 运行与排错

- **立即运行 / 定时运行**：运行详情有整体统计（请求数、解析记录、写入行数、耗时）、
  逐接口结果（状态码、页数、写入行数、`stop_reason`、`duplicates`、错误与建议）、SSE 实时日志（断流自动退轮询）；
- **试抓预览**（不写库）：抓第一页看列、前几行与「预计多少页」；
- **测试落库**：只连目标库，验账号/网络/表名；
- **运行记录**：默认保留最近 300 条，可在列表批量删除或清空。

失败分级：

| 现象 | 含义 | 处理 |
|---|---|---|
| 全部接口失败 | 本次 `failed` | 看接口结果里的 `error` + `hint` |
| 部分失败 | 本次 `passed`，日志有失败数 | 单个接口配置问题，其它照常入库 |
| 连续失败 3 次（跨运行） | 任务自动 `paused` | 修好后点「启用」 |
| 401/403/429 | 会话或限流 | 重新登录 / 调大间隔 |

## 9. 产出文件与清空

### 9.1 下载

用 `xlsx` / `json` / `jsonl`（以及 `sqlite`）落库时，控制台里有下载入口：

| 位置 | 内容 |
|---|---|
| 「接口采集」首页 → **产出文件（可直接下载）** | `data/harvest/` 下全部文件：类型、大小、更新时间、下载 |
| 任务详情 → **产出文件** | 只显示这个任务表名对应的文件 |
| 运行详情 | 顶部「写入目标」直接写着文件绝对路径 |

下载走 `GET /api/collect/files/{name}`（`Content-Disposition: attachment`，点了就下）。
Excel 用 Excel / WPS / Numbers 都能直接打开；JSON 是 `[{...},{...}]`，`json.load` 即可。
也可以直接去 `data/harvest/` 取文件——服务器上就是普通文件。

### 9.2 清空数据

「接口采集」首页右上角 **「清空数据」**，勾选要清的类别，一次清干净（每项都能单独选）：

| 类别 | 清掉什么 | 接口 |
|---|---|---|
| **产出文件** | `data/harvest/` 下的 Excel / JSON / JSONL / SQLite 表格文件 | `DELETE /api/collect/files?all=1` |
| **采集任务与运行记录** | 全部任务配置 + 它们的运行记录 | `DELETE /api/collect/tasks?all=1` |
| **仅运行记录** | 历史运行日志，任务配置保留 | `DELETE /api/collect/runs?all=1` |
| **录制结果** | 内存里的录制会话（含内置浏览器的标签页） | `DELETE /api/collect/captures?all=1` |

规则：

- 每个接口都必须带 `?all=1`，否则直接 400（防止脚本误删）；
- 界面上会先弹一次确认框，写明"要清哪些、多少个"；
- **不可恢复**：数据快照只覆盖录制/设置，不覆盖采集任务与产出文件 —— 要留证据，先下载文件；
- 正在被占用的产出文件（比如别处还开着 `harvest.db`）会被跳过，并提示是哪几个文件。

## 10. 部署（Windows / Linux）

纯 Go（`CGO_ENABLED=0`）+ 纯 Go 数据库驱动，同一份代码两边都能编。

### 10.1 构建

```powershell
go build -o uitest-server.exe .                       # Windows
powershell -ExecutionPolicy Bypass -File scripts\build-all.ps1   # Windows + linux/amd64 + arm64 → dist/
```

### 10.2 Windows 常驻

```powershell
.\start.ps1
schtasks /create /tn "uitest" /tr "E:\workspace\uitest\uitest-server.exe" /sc onstart /ru SYSTEM
```

### 10.3 Linux（systemd）

```ini
# /etc/systemd/system/uitest.service
[Unit]
Description=uitest server
After=network-online.target

[Service]
Type=simple
User=uitest
WorkingDirectory=/opt/uitest
Environment=UITEST_HOST=0.0.0.0
Environment=UITEST_PORT=8490
# 定时任务按本机时区触发，容器默认 UTC，中国服务器务必显式指定
Environment=TZ=Asia/Shanghai
ExecStart=/opt/uitest/uitest-server -config config.json
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now uitest
journalctl -u uitest -f          # [collect] 前缀是采集相关日志
```

Linux 两点注意：

1. **定时抓取本身不需要浏览器**——用的是 Go HTTP 客户端，网络通就能跑；
2. 只有「录制」和 `session.mode=browser` 需要 Chromium 内核。无桌面环境请设
   `browser.headless=true`、`browser.no_sandbox=true`，或直接用 `cookie` 模式。

### 10.4 数据与备份

```
data/
├─ uitest.json     # 录制/运行/采集任务与运行记录/设置
├─ backups/        # 启动时的滚动快照（误删可一键恢复）
├─ harvest/        # 落库产物：harvest.db / <表名>.xlsx / .json / .jsonl
```

迁移机器只需拷 `data/`（`uitest.json` + `harvest/`）。

## 11. 常见问题

**Q：点了「开始录制」没反应 / 浏览器没起来？**
设置 → 内置浏览器 →「诊断浏览器」看内核路径与探测结果；受限环境开 `no_sandbox`，
或填 `debug_url` 连接手工启动的 Chrome。

**Q：录不到请求？**
① 内置浏览器方式：确认操作的是**录制打开的那个标签页**；
② 插件方式：确认「同时录制接口请求」勾着，且页面是在**装/重载插件之后**打开的（改完插件要刷新页面），
浮层应显示 `● 录制中 · N 步 · M 接口`。
也有系统把数据渲染在前端缓存里不发请求，刷新页面再看。

**Q：插件录完，去哪勾选接口、建采集任务？**
三条路：① 停止后插件自动打开「录制结果」页；② 弹窗点「去勾选接口 → 建采集任务」；
③ 控制台首页那行的「勾选接口 → 建任务」。进去后：筛选 → 勾选 → 底部「下一步」。

**Q：删错接口了能恢复吗？**
不能。删除只作用于"这次录制结果"这个临时快照；重录一遍很快，任务与库里数据不受影响。

**Q：列表只抓到第一页 / 抓一半就停？**
看运行详情的「停止原因」：「连续两页数据完全相同」→ 改 `不分页`；「本页 N 条 < 每页 M 条」→ 每页条数填大了；
「已达最大页数」→ 调大最多页数与任务 `max_pages_cap`；什么都没有就一页 → 参数名不对，重新「自动识别分页」。

**Q：抓到一半报 HTTP 429？**
对方在限流。调大「请求最小间隔」（如 3000ms），或拆成多个任务分时段跑。

**Q：落库选 Excel / JSON，文件在哪？**
`data/harvest/<表名>.xlsx|.json`，首页与任务详情都有「产出文件（可直接下载）」卡片。
`upsert` 模式下重复跑不会让行数翻倍。

**Q：定时任务没触发？**
① 任务是否 `paused`（连续失败自动暂停）；② 看「下次触发」；③ 容器时区是否 UTC（`TZ=Asia/Shanghai`）。

**Q：入库中文变问号？**
MySQL 连接串加 `charset=utf8mb4`，库/表也用 `utf8mb4`。

**Q：`upsert` 没生效、数据翻倍？**
「去重键列」必须是真唯一键（如 `id`）；历史数据已有重复时唯一索引建不上，会自动退化为追加，先清表再跑。

**Q：字段突然多一列 / 少一列？**
多列会自动 `ALTER TABLE ADD COLUMN`；少了是这次响应没返回该字段，用「试抓预览」确认。

**Q：能不能并发抓很多接口？**
单任务串行是刻意的。需要更快请建多个任务分别设间隔，而不是把间隔调到 0。
