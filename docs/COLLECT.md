## 1. 它能做什么 / 不做什么

| 做 | 说明 |
|---|---|
| 录下真实请求 | 插件或内置浏览器旁路录制：方法、URL、状态、请求头、请求体、响应体（默认截断 256KB） |
| 筛选与裁剪 | 按方法/类型/状态/关键字/正则筛，逐条或批量删掉不想要的接口 |
| 定时抓取 | 每 N 秒 / 每天 HH:MM / 每周几，带随机抖动；单任务串行，不叠加 |
| 自动翻页 | 页码 / 偏移 / 游标 / 请求体内参数，五种停止条件 + 打转检测 + 跨页去重 |
| 落库 | SQLite、MySQL、PostgreSQL、Excel `.xlsx`、JSON `.json`、JSONL；后三种可在控制台下载 |
| 先看再写 | 「试抓预览」不写库看列与前几行；「测试落库」只验连接 |

**不做**：代理池、UA/指纹伪造、验证码或 WAF 绕过、多账号轮询——这类对抗风控的事不在范围内。
限速、抖动、退避、熔断都是**刻意**的限制：保护对方服务，也保护你自己不被封。

## 2. 5 分钟跑通一条

```powershell
.\scripts\build.ps1 && .\dist\uitest-server-windows-amd64.exe    # 或 .\start.ps1（开发态后台启动）
```

1. 打开 <http://127.0.0.1:8490> → 左侧菜单「接口采集 → 录制接口」；
2. 起始页填 `http://127.0.0.1:8490/demo/api-center.html` → 「开始录制」（会开一个内置浏览器标签页）；
3. 在**那个标签页**里点两下「下一页」（让 URL 里出现 `page=2`）→ 回控制台「停止录制」；
4. 进「录制结果」→ 勾上 `GET /demo/api/goods` →「下一步：配置采集任务」；
5. 定时选「每 1 小时」，落库选 **Excel 表格**，表名 `demo_goods` → 创建 → 「立即运行」；
6. 「执行日志」里能看到这次运行与每个接口的请求 / 响应样本，「产出文件」里下载 `.xlsx`。

示例接口固定 23 条、每页 3 条，所以自动翻页会走 8 页后停在「总数 23 条已抓完」。

### 2.0 用内置 demo 自测「登录态 + 含页面文档」（不需要你的真实系统）

服务自带一套"需要登录"的示例，专门验证会话与录制范围：

| 地址 | 作用 |
|---|---|
| `/demo/collect-login.html` | 登录页：`admin` / `123456`，调 `POST /demo/api/login` → 种 `demo_sid` Cookie + 把 token 写进 `localStorage.demo_token` |
| `/demo/collect-orders.html` | 受保护列表页：每个请求带 `Authorization: Bearer <localStorage 里的 token>` + `X-Tenant: demo`；没登录态接口直接 **401** |

自测步骤（5 分钟）：

1. 浏览器打开 `/demo/collect-login.html` → 点「登录」（token 会变一次，方便验证"用的是最新值"）；
2. 「接口采集 → 录制接口」→ 起始页填 `/demo/collect-orders.html` → **录制范围选「含页面文档」** → 开始录制；
3. 在打开的标签页里点两下「下一页」→ 停止录制；
4. 「录制结果」顶部应显示：`范围 XHR + Fetch + Document · 类型 XHR 3 / Document 1`；
   把「类型」筛选选「文档」能单独列出那条 HTML 请求；
5. 勾选 `GET /demo/api/orders` 建任务 → 「前置登录」配好（或先手工在内置浏览器登录一次）、`浏览器请求头` 保持 **全部共享** → 保存；
6. 「立即运行」→ 运行日志应出现：
   - `会话已就绪：携带 1 个 Cookie（来源：内置浏览器登录态）`
   - `浏览器请求头（auth 模式）：Authorization、X-Tenant …`
   - 每条请求的 `Authorization: Bearer demo-token-…`（就是浏览器里那个最新 token，不是录制时的旧值）
7. 想验证"会不会刷新"：回登录页再登一次（token 变了）→ 再运行 → 日志里的 `Authorization` 应该变成新 token。

> 这里的 42 条订单、每页 5 条，正好可以顺带验证翻页与"总数已抓完"的停止原因。

想一键跑完这些检查（不用手点）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\collect-selftest.ps1
```

它会自己编译、起一个独立实例（独立端口 + 临时数据目录，不动你的 `data/`），依次验证
**登录接口 / 未登录 401 / 带 token 200 / 含页面文档录制 / 建任务并运行**，逐项打印 PASS·FAIL；
失败时会把 `types`、`范围外跳过`、运行日志节选一起打出来。加 `-Keep` 跑完不关服务，可以直接在浏览器里接着手点。

| 执行日志 | `#/collect/runs` | 每次采集的请求 / 解析 / 写入；详情里运行日志逐次记录请求头/请求体/响应体（明文），可勾「只看请求/响应」 |

**让不同接口写不同表 / 不同文件**（两种做法，可叠加）：

1. 任务级分表：任务详情 →「写入目标」→ 勾「每个接口单独分表 / 分文件」。
   表名 = 任务表名 + `_` + 接口名（文件类就是文件名），例如任务表 `goods`、接口「商品列表」→ `goods_商品列表`。
2. 接口级指定：在任务详情展开某个接口 → 填「写入表 / 文件名」。
   填了就以接口为准；留空则按上面的规则（或与任务共用一张表）。

接口级只覆盖「表名 / 文件名」，连接（DSN）、写入模式、批量行数仍沿用任务（也就是「数据写入」里那套配置）。

## 3. 录制：两种方式

| 方式 | 怎么用 | 适合 | 抓取原理 |
|---|---|---|---|
| **浏览器插件**（推荐） | 装 `extension/`，弹窗勾着「同时录制接口请求」，在你自己的浏览器里正常操作 | 已登录的系统、走公司代理/固定 IP、不想再登录一遍 | `net-hook.js` 注入页面主世界，包 `fetch`/`XHR` 记录后批量上报 |
| **内置浏览器** | 「录制接口」卡片填起始页 → 开始录制，服务端开标签页旁路录 | 想干净隔离，或不想动自己的浏览器 | CDP `Network` 域旁路监听 |

两种方式录到的结果完全一样，进同一份「录制结果」；后续筛选、删除、建任务流程也一样。

**录什么 / 不录什么**（重要）：

- **录**：接口地址、查询参数、请求体、响应样本；
- **不录请求头里的登录态**：`Cookie`、`Authorization`、`User-Agent`、`Referer`、`Host` 这类一律不进录制结果
  （只保留 `Content-Type` 这一个"请求参数"级别的头）。这些值在运行时由「前置登录 + 浏览器会话」统一提供，
  存进任务只会变成一份过期死值——早期版本正是因为存了 `Cookie`，才会出现"日志里 Cookie 重复"和"用了旧 token"。

**插件方式的细节**：

- 弹窗里能看到「已录接口 N 条」，页面右下角浮层显示 `● 录制中 · N 步 · M 接口`；
- 停止录制后**自动打开「录制结果」页**（弹窗里「停止录制后自动打开」可关），也可点「去勾选接口 → 建采集任务」；
- 自动跳过 `服务端地址/api/` 前缀（不录平台自己）与 `chrome-extension://`；
- 抓不到的：二进制响应（图片/文件）、`EventSource`/`WebSocket` 流数据；
- 页面在装/重载插件之前就打开的话，刷新一次即可；
- 插件崩了会话会一直「录制中」——30 分钟无上报自动判停，也可在列表里「丢弃」。

### 3.1 登录态（只有一种：浏览器会话 + 前置登录）

**思路很简单**：先用「前置登录（UI 自动化）」把内置浏览器真的登进去，然后抓取时
**Cookie 和请求头全部从浏览器里取**——只有 URL / 请求体这些**请求参数**按接口配置。

```
前置登录（UI 自动化） → 浏览器里就是最新登录态
        ↓
导出 Cookie + 浏览器实时请求头（Authorization / User-Agent / X-* …）
        ↓
逐条抓接口：URL + 查询参数 + 请求体用接口配置，其余全用浏览器的
```

- 会话来源**只有这一种**：`手工 Cookie` / `无会话` 等入口已经移除（老任务里存的值一律按浏览器会话处理）；
- 「浏览器请求头」三档：**全部共享**（默认，除请求参数外的头都用浏览器实时值）/ 只共享鉴权头 / 不共享；
- 站点留空 = 自动用任务起始页或第一个接口的域名；
- 30 分钟内复用导出的会话；登录之后再跑会先作废旧缓存，避免用过期 Cookie。

**为什么必须这么干**：接口里录制下来的 `Authorization` / `X-Token` 是**录制那一刻**的值，登录之后早就换了；
只搬 Cookie 不搬请求头，就会出现"看起来带了鉴权头，实际全是 401"。

运行日志会明说这次用了什么：

```
会话已就绪：携带 3 个 Cookie（来源：内置浏览器（Cookie + 请求头））
浏览器请求头（all 模式）：authorization、user-agent、x-tenant —— 与接口里的同名头冲突时用浏览器实时值
```

一条都没抓到时也会 warn 提示"Authorization 可能还是录制时的旧值"，并建议把站点改成登录后一打开就请求接口的页面。

### 3.2 Token 型站点（`Authorization: Bearer …`）

**界面上已经不再单独配 Token** —— token 型站点直接用 3.1 的机制覆盖：

1. 用 **前置登录（UI 自动化）** 把浏览器真的登进去（3.3）；没配前置登录时，就用内置浏览器里**当前已有的**登录态；
2. 「浏览器请求头」保持 **全部共享**（默认）即可，`Authorization` 自然一起共享；

运行时会打开站点、抓一个真实接口请求，把它的 `Authorization` / `Blade-Auth` / `X-Token` 等**连同 Cookie、User-Agent 一起**抄过来，
抓取时覆盖接口里录制下来的过期值；不需要任何额外配置。

确认方法：运行日志里的
`浏览器请求头（all 模式）：authorization、user-agent、x-tenant`、以及每条请求的 `请求头 Authorization: Bearer …`；
自检里的「请求头共享」一步会直接给出新旧值对比。

> 老任务里如果还留着 `session.token` 配置，后端仍然按原逻辑生效（界面上不再显示），不会被这次改动破坏。

### 3.3 前置登录：先跑一段 UI 自动化，再抓数据

最省心的办法——**真的在浏览器里点一遍登录**，然后才导出会话去抓接口。适合：

- 登录流程复杂（验证码之外还有滑块之外的多步、短信、单点跳转、需要点"进入系统"）；
- token / Cookie 随登录状态变化，手工维护不住；
- 想在登录失败时看到截图（哪一步点不到、报什么错）。

配置（任务详情 →「前置登录（UI 自动化）」）：

| 参数 | 说明 |
|---|---|
| 登录流程录制 | 在「UI 自动化」里先录一段：打开登录页 → 输账号密码 → 点登录（可加"等待元素/校验跳转"）。这里选它 |
| **登录用变量** | **必填**：一行一个 `password=真实密码`。录制器出于安全会把密码框**脱敏成 `{{password}}`**，回放时必须靠它注入，否则填进去的是字面量 `{{password}}`，登录必然失败（但运行状态可能仍是"通过"，很有迷惑性）。值支持 `{{env:SITE_PASS}}`，把密码放环境变量更安全 |
| 触发时机 | `always` 每次运行前都跑（默认）｜ `on-fail` 只在会话失效（接口 401/403）时补跑一次 |
| 超时 | 整个登录流程的上限，默认 180 秒 |
| 登录失败也继续抓 | 默认关闭：登录失败本次运行直接失败，不放行空数据 |
| 现在跑一次 | 立刻走一遍登录 + 导出会话，并把「Cookie 几个」显示出来 |

> 前置登录跑完如果**一个 Cookie 都没导出**，本次运行会直接失败并提示原因（而不是继续用无登录态请求打一串 401）。

运行时会发生什么：

1. 采集开始 → 先按录制回放登录（用的是同一个内置浏览器 profile，所以登录态真被刷新）；
2. 登录一结束就**把该站点的 Cookie / 请求头缓存全部作废**，再重新导出——拿到的一定是刚登录后的会话；
3. 导出会先按接口 URL 精确取 Cookie，取不到就**退回全库取再按域名过滤**（登录发生在别的子域也兜得住）；
   同时抓一条页面真实接口请求，把它的请求头（`Authorization` / `User-Agent` / `X-*`）整份共享给后续抓取；
4. 然后才逐接口抓取。整个过程在运行日志里看得见：`▶ 前置登录：执行「登录流程」…` /
   `前置登录完成（8.2s），会话已刷新` / `会话已就绪：携带 6 个 Cookie（来源：…）` / `Cookie 名单：SID、token_merchant、…`；
5. 登录失败时日志里带 UI 自动化运行记录 id，去「UI 自动化 → 运行记录」打开能看到那一步的截图和定位结果；
6. `on-fail` 模式下，抓取中途遇到 401/403 会**自动补跑一次登录**，然后重试当前请求（每次运行每个接口只补一次，避免死循环）。

> 前置登录负责"真的登进去"，浏览器会话导出负责"把 Cookie 与请求头搬到 HTTP 请求上"；
> 两者叠起来就是完整的登录态（老任务里的 `session.token` 仍按原逻辑兼容，见 3.2）。
>
> ⚠️ 「试抓预览」**不会**跑前置登录（它只发一次请求看结构）。想验证"登录 + 导出"这条链路，
> 点任务详情右上角的 **「自检」**：它会按
> `会话配置 → 前置登录 → 浏览器 Cookie → 导出会话 → 真发一次请求` 逐步给出 ✔/✘ 和明细
> （Cookie 名字、条数、请求状态码、响应片段），哪一步红了一眼就能定位。

### 3.4 录制小技巧

- 想抓"翻页"接口就真的翻两页——这样 `page` 参数会被识别出来；
- 列表接口自带"空结果页"也不用管，抓到空页会自动停；
- 页面用了强缓存看不到请求时，把「录制范围」改成 **含页面文档（XHR + Fetch + Document）**：会额外录下页面本身（HTML）的请求；
  这个选择会记住，录完在「录制结果」顶部能看到 `范围 XHR + Fetch + Document` 和 `类型 XHR 12 / Document 2` 的统计，
  一眼确认生效没有（插件录制只上报接口，不会有页面文档）；
- 内置浏览器方式最多同时保留 5 个录制会话，旧的自动关闭。

## 4. 筛选与裁剪

「录制结果」页（`GET /api/collect/captures/{id}`）的筛选全部走服务端：

| 筛选 | 作用 |
|---|---|
| 关键字 | 匹配 URL / 路径 / 主机 |
| 方法 | GET / POST / PUT / PATCH / DELETE |
| 类型 | XHR / Fetch / Document |
| 状态 | 2xx / 4xx / 5xx（API 也可用 `min_status` / `max_status`） |
| 只看 | `JSON 响应`（推荐）/ `有响应体` |
| include 正则 | 只保留 URL 命中的，如 `/api/(goods\|orders)` |
| exclude 正则 | 排除噪声，如 `heartbeat\|log\|collect\|sentry` |

典型用法：`include=/api/` + `exclude=heartbeat|log` + `只看=JSON 响应`，一屏就干净了。

点某行「查看」看响应体结构：自动识别**记录数组在哪**（如 `data.list`）、推测字段映射、给出前几行预览——
这份预览就是后面入库的列。

### 4.1 删掉不想要的接口

| 操作 | 怎么做 | 效果 |
|---|---|---|
| 删单条 | 该行右侧「删除」 | 只从这次录制结果移除这一条 |
| 批量删 | 勾选几行 → 底部「删除选中（N）」 | 一次移除多条 |
| 按条件删 | 先筛出噪声（如 `exclude=heartbeat`）→「全选当前筛选结果」→「删除选中」 | 批量清理噪声 |
| 清空这次录制 | 右上「删除这次录制」 | 整个会话丢弃（任务与已入库数据不受影响） |

删除是真删：不会出现在列表、筛选统计、建任务的可选范围里；插件即使重发同一条也会被忽略（按请求 id 幂等）。
两类来源都支持（插件录制直接摘数据，内置浏览器录制走"屏蔽名单"）。

## 5. 建采集任务

勾选接口 →「下一步：配置采集任务」→ 四段配置（定时 / 限速 / 落库 / 会话）。

**任务详情按页签分区**，不再是一页长表单：

| 页签 | 放什么 |
|---|---|
| **概览** | 任务名称 / 说明 / 起始页，以及最近运行状态 |
| **公共参数** | 所有接口共用的 query/body 参数、公共请求头、登录后脚本（见 5.35） |
| **登录** | 浏览器会话（站点、请求头共享策略）+ 前置登录（UI 自动化） |
| **接口设计** | 每个接口的方法 / URL / 记录路径 / 分页 / 请求头 / 请求体 / 字段映射 / 写入表（见 5.0、7.x） |
| **调度与落库** | 定时计划、礼貌限速、写入目标（见 5.1–5.3） |
| **文件产出** | 这个任务产出的 Excel / JSON / JSONL，直接下载（写 MySQL / PG 时提示"没有文件产出"） |
| **最近运行** | 这个任务最近 20 次运行，点进去看明文报文、SQL 与停止原因 |

页签只切换显示，字段 id 不变，保存时照样一次提交全部配置。
「文件产出」「最近运行」以前堆在页面底部，现在是独立页签，各自带刷新与空态提示。

任务详情里**每个接口是一个可折叠的块**：点标题左侧 `▸` 展开、`▾` 收起，
标题行显示摘要（`GET · 页码分页 · 3 字段 · 写入 表名`）。折叠只影响显示，不会丢未保存的修改。

接口多的时候有两个省事按钮（都在接口块标题行）：

- **试抓**：只抓这一个接口的第一页（不写库），改完 URL / 请求体 / 分页后立刻验证，不用跑整个任务；
- **分页套用全部**：把这个接口的分页配置（翻页方式 / 参数名 / 位置 / 每页条数 / 条数参数名 / 起始值 / 总数与结束字段）复制到所有接口；
- **请求头套用全部**：把这个接口的请求头复制到所有接口（比如多接口共用 `X-Tenant`）。

这些都是"改表单 + 试抓会自动先保存"，最终点「保存配置」生效。

### 5.0 接口里能看到、也能改「请求数据」

采集任务就是回放录制会话里的那几条请求，所以**建任务时会把每条请求的原始信息存一份快照在接口上**，
之后在任务详情展开任一接口：

**可编辑（保存后抓取就用你改的）** —— 收在「请求头 / 请求体（可改）」折叠区里，点标题展开：

| 字段 | 说明 |
|---|---|
| 请求头 | `Name: Value` 一行一个，自己增删改都行；值里可用 `{{env:NAME}}`。Cookie / Authorization / User-Agent / Referer / Host 由「登录态」提供，**写这里也不会发**（运行时会自动忽略，避免用过期的登录态） |
| 请求体 | 原样发送的请求体，支持 `{{page}}` `{{date}}` `{{timestamp}}` `{{env:NAME}}`；分页用「请求体 JSON」时会自动改写翻页字段 |

> 现在录制只保留 `Content-Type` 这一个头，所以新任务的「请求头」默认只有一行；
> 需要额外业务头（如 `X-Tenant`）时，建议配在「公共参数 → 公共请求头」里，改一处全接口生效。

**只读快照（「录制时的请求数据」折叠区）**

| 内容 | 说明 |
|---|---|
| 请求头 | 录制那一刻留下的请求头（新版只留 `Content-Type`；老录制可能含 `Cookie` / `Authorization`，仅作参考，不会发出） |
| 请求体 | 录制时的 `POST/PUT` 请求体（截断 16KB） |
| 来源 | 录制时间、触发请求的页面地址、录制请求 id |

快照下面有三个按钮：**填入请求头 / 填入请求体 / 全部填入** —— 把录制值搬进上面可编辑的输入框
（点按钮会自动展开「请求头 / 请求体」折叠区），再手改（比如换 `store_id`、减字段、加 `X-Tenant`），点「保存配置」生效。
填入请求头时会自动跳过 `Cookie` / `User-Agent` / `Referer` / `Host` / `Content-Length` / `sec-*`
（这些归「会话」管，钉死会变成过期登录态）。

> 响应样本另外存着，只服务「字段映射 → 从样本重新识别」和分页推断，不在这个区块里展示。
> 老任务（在加这个功能之前建的）没有快照，接口块里会提示"没有录制快照"，重录一遍接口重建任务即可带上。

### 5.1 定时计划

| 模式 | 参数 | 说明 |
|---|---|---|
| 固定间隔 | 间隔（秒）+ 触发抖动 % | 每 N 秒一次；抖动在 ±p% 内随机，避免整点扎堆 |
| 每天定时 | 每日时刻（`09:00,21:30`）+ 每周几（`1,3,5`，空=每天） | 到点触发，带 0–5 分钟抖动 |
| 仅手动 | — | 只在你点「立即运行」时跑 |

服务端规则：

- `next_run_at` 由服务端维护，列表直接显示；
- **重启不补跑**错过的点，顺延到下一个时间（避免一开机打一串请求）；
- 上一轮没跑完时下一轮直接跳过（不叠加）；
- 调度粒度 10 秒，「每天 09:00」实际在 09:00:00–09:00:10 之间触发。

### 5.2 礼貌限速与容错

| 参数 | 默认 | 作用 |
|---|---|---|
| `min_interval_ms` | 1000 | 相邻请求最小间隔（低于 200 会被拉回默认值） |
| `jitter_percent` | 30 | 间隔随机抖动 ±p% |
| `timeout_ms` | 20000 | 单请求超时 |
| `retries` | 2 | 失败重试（指数退避；429/503/5xx/网络错误才重试） |
| `backoff_ms` | 1500 | 退避基数 |
| `max_fail_streak` | 3 | 连续失败几个接口就熔断本次运行 |
| `max_pages_cap` | 50 | **分页默认上限**：只在接口没填「最多页数」时生效；接口填了就以接口为准（硬顶 2000） |

> 想抓 500 页？直接把接口的「最多页数」填 500 即可 —— 这个值不会被任务的默认上限压回去，
> 只有超过 2000 才会被夹到 2000。填 `0`/留空才回落到任务的「分页默认上限」。

遇到这些状态**立刻停手**，原因写进运行详情：

| 状态 | 含义 | 处理 |
|---|---|---|
| `401` / `403` | 会话失效或被拒 | 重新登录再录一遍，或更新 Cookie |
| `429` | 被限流 | 停后续接口，调大间隔重试 |
| 其它 4xx | 参数/路径不对 | 不重试，直接报错 |

### 5.3 落库

| 驱动 | 产物 | 说明 |
|---|---|---|
| `sqlite`（默认） | `data/harvest/harvest.db` | 零依赖，可填相对/绝对路径 |
| `xlsx` | `data/harvest/<表名>.xlsx` | **Excel 表格**，可下载；表头加粗 + 冻结首行，数字按数字存 |
| `json` | `data/harvest/<表名>.json` | **JSON 文件**（对象数组），可下载 |
| `jsonl` | `data/harvest/<表名>.jsonl` | 追加写，pandas / DuckDB / jq 直接读 |
| `mysql` | 数据库表 | DSN：`root:pass@tcp(127.0.0.1:3306)/test?charset=utf8mb4&parseTime=true` |
| `postgres` | 数据库表 | DSN：`postgres://user:pass@127.0.0.1:5432/test?sslmode=disable` |

都是纯 Go 驱动，不需要 CGO 或本地客户端库。行为：

- **SQL 类**：表不存在自动 `CREATE TABLE`（整数→`INTEGER`、小数→`REAL`、文本→`TEXT`、对象/数组→JSON 文本）；
  响应多出字段自动 `ALTER TABLE ADD COLUMN`；`upsert` 按「去重键列」建唯一索引并覆盖；
- **文件类**：文件不存在自动创建；`xlsx` / `json` 每次**整份重写**（表头随字段增长），
  `upsert` 同样按去重键覆盖，行数不会随运行次数翻倍；`jsonl` 只追加；
- 每行自动带 `_fetched_at`（采集时刻），方便排查与去重。

> 表名建议全小写；Excel/JSON 的文件名就是表名，`/` `\` 等字符会自动替换成 `_`。
>
> **连接串（DSN）不在任务里填**：在「数据写入」里统一配好，任务详情只选**数据库类型 + 表名**
> （引用某套「数据写入」配置时会自动把它的连接串带过来）。

### 5.35 公共参数（所有接口共用）

任务详情「公共参数」页签：所有接口共用一份，登录后能被自动刷新成最新值。

| 字段 | 作用 |
|---|---|
| 公共查询参数 / 请求体字段 | 一行一个 `key=value`。**GET/DELETE 并进 URL 查询串；POST/PUT/PATCH 并进 JSON 请求体**（接口自己同名时不覆盖） |
| 公共请求头 | 一行一个 `Name: Value`；值里写了 `{{变量}}` 时优先级很高，会**盖掉**浏览器里的同名实时头 |
| 公共 Cookie | 一行一个 `name=value`；只是默认值，前置登录后浏览器里的同名 Cookie 优先 |
| 参数绑定 | 一行一个 `参数名 -> header:头名 / cookie:名 / query:名 / body:字段 [= 值模板]`，优先级最高 |
| 登录后自动刷新 | 勾选后，每次运行 / 试抓都先从浏览器请求头 / Cookie / 本地存储取最新值写进参数，再发请求 |
| 登录成功后执行的脚本 | 在登录后的内置浏览器页面里跑，可读 `localStorage` / `document.cookie`；返回 JSON 字符串 |

三个工具按钮：

| 按钮 | 做什么 |
|---|---|
| 粘贴导入（Cookie / Header / cURL） | 从 DevTools 复制 Cookie、请求头、参数或整条 cURL 粘进去，自动拆成公共 Cookie / 请求头 / 参数，鉴权头自动转成 `{{token}}` 绑定；**只合并不覆盖**，点「保存配置」才生效 |
| 从录制汇总 | 把选中接口里「每个接口都一样」的 query/body/请求头/Cookie 提出来（分页参数自动排除）；建任务弹窗按选中的录制请求汇总，任务详情按 `created_from` 反查 |
| 登录后刷新（任务详情） | 按当前登录态重新导出一次会话并刷新公共参数，弹窗给出脱敏后的参数 / Cookie / 请求头 / 生效绑定，用来确认新 token 到底通没通；只读，不改配置 |

优先级（后者覆盖前者）：

```
公共参数
→ 接口自己的 URL / 请求头 / 请求体
→ 公共 Cookie
→ 前置登录后的浏览器 Cookie / 请求头
→ 值里带 {{变量}} 的公共请求头
→ 参数绑定（header / cookie / query / body，优先级最高）
→ 登录后脚本
```

**典型场景：登录换了 token，请求头里还是旧的**

1. 「登录」页签配好前置登录（UI 自动化录制）；
2. 公共参数里勾「登录后自动刷新」，`token 写进哪个参数` = `token`（「从哪个请求头取」留空 = 自动找 `Authorization`）；
3. 参数绑定填一行 `token -> header:Authorization = Bearer {{token}}`（不填也行：刷新时发现没有绑定会自动补一条一样的）；
4. 之后每次运行 / 试抓：前置登录 → 导出浏览器会话 → 刷新参数 `token` → 绑定写进 `Authorization`，用的永远是刚登录的 token。

其他常见用法：

```
sid -> cookie:SESSION                        # 把参数写进 Cookie
uid -> query:user_id                         # 把参数并进 URL 查询串
token -> header:X-Token = {{token}}          # 换个头名 / 换模板
```

「登录后自动刷新」里还能配 Cookie → 参数（如 `SESSION=sid`）和浏览器存储 → 参数（如 `localStorage:token=token`）；
读不到会在运行日志里留一条 warn，不会让整轮失败。

脚本写法（返回值必须是 JSON 字符串）：

```js
// 1) 把登录拿到的 token 灌进公共参数
return JSON.stringify({ params: { token: localStorage.getItem('token_merchant') } })

// 2) 直接给请求头（也可以只返回 {token:"…"}，会自动写成 Authorization: Bearer <token>）
return JSON.stringify({
  headers: { 'X-Tenant': localStorage.getItem('tenant_id') },
  params: { lang: 'zh-CN' }
})
```

运行日志会告诉这次并进去了什么：`公共参数：query/body 3 项（tenant_id、token、page）` /
`登录后刷新公共参数：参数:token、绑定:Authorization`。

**公共参数里的键可以直接当变量用**：接口 URL / 请求体里写 `{{token}}`、`{{tenant_id}}` 都会被替换成公共参数（或脚本产出）的值，
例如 `https://api.x.com/list?access_token={{token}}`。内置变量 `{{page}} {{date}} {{timestamp}} {{uuid}}` 照旧可用。

> 接口自己已经有同名参数时，**以接口为准**（公共参数只补缺）；分页参数也接口优先，粘贴导入 / 从录制汇总时直接跳过。
> MySQL 记得 `charset=utf8mb4`，否则中文变问号。

## 6. 记录路径 / 字段映射 / 变量

### 6.1 记录路径（`records_path`）

响应里"记录数组"的位置，点「查看」通常自动填好：

```
{"code":0,"data":{"total":6,"list":[{...}]}}   → data.list
[{...},{...}]                                  → 留空（响应本身就是数组）
{"data":{"item":{...}}}                        → 自动按单条记录处理
```

留空时服务端自动找"最像列表"的数组（元素是对象、元素最多、层级最浅）。

### 6.2 字段映射（列名 ← 路径）

| 路径写法 | 含义 |
|---|---|
| `id` / `name` | 顶层字段 |
| `owner.name` | 嵌套对象 |
| `list[0].price` | 数组下标 |
| `@now` `@datetime` | 采集时刻 |
| `@date` / `@timestamp` | 采集日期 / 时间戳 |
| `@url` / `@endpoint` / `@page` | 当前接口 URL / 接口名 / 页码 |

列名允许中文，但建议英文小写 + 下划线，跨库更稳。
没配字段时运行会按响应自动识别，并在日志里提示"建议保存字段映射"。

### 6.3 URL / 请求体里的变量

```
https://api.example.com/goods?page={{page}}&day={{date}}
```

| 变量 | 值 |
|---|---|
| `{{page}}` | 当前页码（分页时自动递增） |
| `{{now}}` `{{date}}` `{{datetime}}` `{{timestamp}}` | 本地时间 / 日期 / 秒级时间戳 |
| `{{uuid}}` | 随机 UUID |
| `{{host}}` | 接口所在主机 |
| `{{env:NAME}}` | 读环境变量（**密钥放环境里，别写进任务**） |

## 7. 分页抓取

列表接口几乎都分页；只抓第一页 = 只拿一页，所以这块决定"能不能抓全"。

### 7.1 三种翻页方式

| 方式 | 长什么样 | 典型场景 |
|---|---|---|
| **页码** | `?page=1` / `?pageNo=2` / `?current=3` | 后台管理列表 |
| **偏移** | `?offset=0&limit=20` → `offset=20,40…` | 开放 API、ES 风格 |
| **游标** | 响应给 `next_cursor`，下次带上 | 深分页、时间线、Feed |

参数放 **URL** 或 **请求体（POST JSON）** 都支持：「参数位置」选 **自动**（POST/PUT/PATCH 进请求体、GET/DELETE 进 URL，推荐）、URL 参数、请求体 JSON。

### 7.2 自动识别（什么都不填就行）

录制时那条请求 + 响应样本会被用来推断：翻页参数名、每页条数、总数字段
（`data.total` / `totalCount` / `recordsTotal`…）、`has_more` 类结束标志、游标路径。
建任务时已填好，分页框上方显示总结：

```
分页  页码分页：page，每页 3 条，总数取自 data.total，最多 9 页     [自动识别分页]
```

不准就点「自动识别分页」重算，或手工改：

| 字段 | 说明 |
|---|---|
| 翻页方式 | 自动 / 页码 / 偏移 / 游标 / 不分页 |
| 参数名 | `page` / `offset` / `cursor`（按你的接口写） |
| 参数位置 | 自动（POST 进请求体、GET 进 URL）/ URL 参数 / 请求体 JSON |
| 每页条数 | 判断"最后一页"与偏移步长 |
| 条数参数名 | `size` / `limit` / `pageSize` 这类名字：填了就会把「每页条数」一起发出去（和页码参数同进 query 或 body） |
| 最多页数 | 安全阀。**填了就以你填的为准**（硬顶 2000 页）；留空则用任务的「分页默认上限」（默认 50） |
| 起始值 | 页码从 1 还是 0 开始 |
| 总数字段 | 如 `data.total`（有它就能精确停） |
| 结束标志 | 如 `data.has_more`（false 就停） |
| 游标字段 | 如 `data.next_cursor` |
| 短页即止 | 返回条数 < 每页条数 → 认为最后一页 |

### 7.3 五个停止条件（满足任一即停）

1. 本页返回 **0 条**；
2. 本页条数 **< 每页条数**（短页即止，可关）；
3. 响应里的 **总数已抓完**（`ceil(total / page_size)` 页）；
4. **`has_more = false`**，或游标为空/不再变化；
5. 达到 **最多页数**（你自己填的值，硬顶 2000；留空时用任务的「分页默认上限」，默认 50）。

外加两条安全行为：

- **原地打转检测**：连续两页内容完全一致（典型原因：接口根本不吃 `page`）→ 立刻停，
  运行详情写「连续两页数据完全相同，判定接口忽略了分页参数」，不会傻跑 50 页；
- **跨页去重**：同一行在多页重复出现时跳过，运行详情显示「去重 -N」。

运行详情里的样子：

```
▶ 采集接口 GET https://example.com/api/goods?page=1&size=3
分页策略：页码分页：page（从 1 起，最多 9 页，每页约 3 条，总数取自 data.total）
第 1 页：3 条（累计 3 条）
...
第 8 页：2 条（累计 23 条）
停止翻页：总数 23 条已抓完（每页 3 条）
```

### 7.4 常见分页坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 只抓到第一页 | 参数名猜错（接口用 `pageNo`，配成了 `page`） | 在浏览器翻一页看 URL 真实参数名，或改「参数名」 |
| 抓了 50 页全是同一批 | 接口不吃分页（前端本地分页 / 一次返全量） | 改成 `不分页`；系统也会自动停并提示 |
| 第 2 页起就没数据 | 页码从 0 开始，或需同时传 `page_size` | 把「起始值」改成 0；检查每页条数 |
| 游标模式只抓一页 | 游标字段路径写错 | 填完整路径，如 `data.next_cursor` |
| POST 接口翻不动 | 参数在请求体里却写进了 URL | 「参数位置」改 `请求体 JSON` |
| 总数对不上（少几条） | 抓取期间数据在变 | 正常；用 `upsert` + 唯一键，跑两次对齐 |

## 8. 运行与排错

- **立即运行 / 定时运行**：运行详情有整体统计（请求数、解析记录、写入行数、耗时）、
  逐接口结果（状态码、页数、写入行数、`stop_reason`、`duplicates`、错误与建议）、SSE 实时日志（断流自动退轮询）；
- **运行日志里有明文报文**：每一次请求都记两行 —— `→ 方法 URL #第几次` + 请求头/请求体，`← 状态码 大小` + 响应体。
  Cookie、Authorization 都**原样明文**（方便确认登录态和参数是否真的生效），分页抓 N 页就有 N 组；
  报文按结构显示：一行一个请求头（`key  value` 两列，长 JWT 自动换行）、请求体/响应体默认折叠（JSON 自动缩进），
  日志区右上有「展开报文 / 折叠报文」一键切换，还可以勾「只看请求/响应」「只看 SQL」把业务日志滤掉；
  **请求报文（请求行 / 请求头 / 请求体）永远完整**，不截断也不省略（只有单条 > 1MB 的极端请求体才截断并标注）；
  响应体单条最多 32KB，本次运行响应体总量超 1MB 后只记摘要（请求依旧完整）；单次运行日志总量 2MB 兜底，
  超出时从**最老的日志**开始丢，剩余报文完整性不受影响；
- **试抓预览（不写库）**：抓第一页看列、前几行与「预计多少页」；每条接口还能展开**明细**，看清楚这次到底发了什么 ——
  请求方法 / URL / 最终请求头 / query 参数 / 请求体 / 展开后的变量 / 重试次数 / 耗时，响应状态 / 响应头 / 大小 / 响应体预览，
  以及「会话 → 公共参数 → 变量 → 分页 → 请求 → 响应」的过程说明；Cookie / Authorization / password 一律打码，明细可一键复制，
  直接贴给别人排查不会泄漏登录态；
- **落库 SQL 也进日志**：真正执行到数据库的语句逐条打印（`SQL` 绿色、等宽字体、可直接复制去库里跑）——
  建表 / 补列 / 建唯一索引、`INSERT` 预编译模板、以及**每批数据展开后的整句 SQL**（字面量已内联，单批最多展示 5 行，其余注明行数）；
  一次运行最多打 60 条，超出只留一条摘要，避免把日志撑爆；
- **测试落库**：只连目标库，验账号/网络/表名；
- **运行记录**：默认保留最近 300 条，可在列表批量删除或清空。

失败分级：

| 现象 | 含义 | 处理 |
|---|---|---|
| 全部接口失败 | 本次 `failed` | 看接口结果里的 `error` + `hint` |
| 部分失败 | 本次 `passed`，日志有失败数 | 单个接口配置问题，其它照常入库 |
| 连续失败 3 次（跨运行） | 任务自动 `paused` | 修好后点「启用」 |
| 401/403/429 | 会话或限流 | 重新登录 / 调大间隔 |

### 8.1 跑完推企业微信群（成功 / 失败都推）

**在「设置 → 运行通知」里配一次，所有采集任务共用**（不再按任务单独配）：

| 字段 | 说明 |
|---|---|
| 启用运行通知 | 总开关 |
| Webhook 地址 | 企业微信群 → 右上角设置 → **群机器人** → 添加 → 复制 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…` |
| 成功时推送 / 失败时推送 | 两个都默认勾上，按需关掉其中一个 |
| @ 谁 | 逗号分隔的 userid 或手机号，`all` = @所有人；**填了会改用 text 消息**（企业微信 markdown 不支持 @） |
| 详情链接前缀 | 填 `http://你的地址:8490`，消息末尾会带一条「查看运行日志」链接 |

流程：任务一跑完（`passed` / `failed`）→ 异步推一条（**不拖慢采集，推失败只记一条 warn 到运行日志**）：

```
# ✅ 接口采集成功
> 任务：**商品采集**
> 状态：成功
> 触发：定时触发
> 时间：2026-11-06 14:42:56
> 接口：3 个（成功 3 / 失败 0），请求 12 次，写入 340 行
> 耗时：8.2s
> 写入：SQLite 表 demo_goods
> 明细：商品列表 300 行、库存 40 行

[查看运行日志](http://127.0.0.1:8490/#/collect/runs/run_xxx)
```

失败时额外逐条带「哪个接口 + 原因」（最多 3 条）：

```
> 错误：第 2 页返回 401
> 失败：「商品列表」接口返回 401：登录态失效
```

点「发一条测试」可以先验证 webhook 通不通：

```bash
curl -X POST "http://127.0.0.1:8490/api/settings/notify/test"
```

> 取消运行（`canceled`）不推送，避免误报。
> 企业微信侧限流是 **20 条/分钟**，一小时级任务完全够用；秒级任务请别开通知。

## 9. 产出文件与清空

### 9.1 下载

用 `xlsx` / `json` / `jsonl`（以及 `sqlite`）落库时，控制台里有下载入口：

| 位置 | 内容 |
|---|---|
| 「接口采集」首页 → **产出文件（可直接下载）** | `data/harvest/` 下全部文件：类型、大小、更新时间、下载 |
| 任务详情 → **产出文件** | 只显示这个任务表名对应的文件 |
| 运行详情 | 顶部「写入目标」直接写着文件绝对路径 |

下载走 `GET /api/collect/files/{name}`（`Content-Disposition: attachment`，点了就下）。
Excel 用 Excel / WPS / Numbers 都能直接打开；JSON 是 `[{...},{...}]`，`json.load` 即可。
也可以直接去 `data/harvest/` 取文件——服务器上就是普通文件。

### 9.2 清空数据

「接口采集」首页右上角 **「清空数据」**，勾选要清的类别，一次清干净（每项都能单独选）：

| 类别 | 清掉什么 | 接口 |
|---|---|---|
| **产出文件** | `data/harvest/` 下的 Excel / JSON / JSONL / SQLite 表格文件 | `DELETE /api/collect/files?all=1` |
| **采集任务与运行记录** | 全部任务配置 + 它们的运行记录 | `DELETE /api/collect/tasks?all=1` |
| **仅运行记录** | 历史运行日志，任务配置保留 | `DELETE /api/collect/runs?all=1` |
| **录制结果** | 内存里的录制会话（含内置浏览器的标签页） | `DELETE /api/collect/captures?all=1` |

规则：

- 每个接口都必须带 `?all=1`，否则直接 400（防止脚本误删）；
- 界面上会先弹一次确认框，写明"要清哪些、多少个"；
- **不可恢复**：数据快照只覆盖录制/设置，不覆盖采集任务与产出文件 —— 要留证据，先下载文件；
- 正在被占用的产出文件（比如别处还开着 `harvest.db`）会被跳过，并提示是哪几个文件。

## 10. 部署（Windows / Linux）

纯 Go（`CGO_ENABLED=0`）+ 纯 Go 数据库驱动，同一份代码两边都能编。

### 10.1 构建

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1          # 当前平台 → dist\
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -All     # windows/amd64 + linux/amd64 + linux/arm64
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Clean   # 先清空 dist\ 再编

# 不走脚本也行：
go build -o uitest-server.exe .                                     # 单平台
```

`dist\` 里除二进例外还会带一份 `config.json`（从该目录启动 exe 也能读到监听地址/端口）和 `BUILD.txt`（编译时间、Go 版本、目标平台）。

### 10.2 Windows 常驻

```powershell
.\start.ps1                                              # 开发态：后台启动，日志 data-start.log
.\dist\uitest-server-windows-amd64.exe -host 0.0.0.0     # 正式跑：直接前台/服务方式启动
schtasks /create /tn "uitest" /tr "E:\workspace\uitest\dist\uitest-server-windows-amd64.exe" /sc onstart /ru SYSTEM
```

### 10.3 Linux（systemd）

```ini
# /etc/systemd/system/uitest.service
[Unit]
Description=uitest server
After=network-online.target

[Service]
Type=simple
User=uitest
WorkingDirectory=/opt/uitest
Environment=UITEST_HOST=0.0.0.0
Environment=UITEST_PORT=8490

Restart=always

[Install]
WantedBy=multi-user.target
```

```bash

journalctl -u uitest -f          # [collect] 前缀是采集相关日志
```

Linux 两点注意：

1. **抓接口走 Go HTTP 客户端**，网络通就能跑；但登录态要从内置浏览器导出，
   所以运行任务的机器仍然要能起 Chromium（`browser.debug_url` 也可指向另一台机器）；
2. 「录制」和「采集」都要 Chromium 内核。无桌面环境请设
   `browser.headless=true`、`browser.no_sandbox=true`，或用 `browser.debug_url` 接一个现成的 CDP 端点。

### 10.4 数据与备份

```

├─ uitest.json     # 录制/运行/采集任务与运行记录/设置
├─ backups/        # 启动时的滚动快照（误删可一键恢复）
```

## 11. 常见问题

**Q：点了「开始录制」没反应 / 浏览器没起来？**
设置 → 内置浏览器 →「诊断浏览器」看内核路径与探测结果；受限环境开 `no_sandbox`，
或填 `debug_url` 连接手工启动的 Chrome。

**Q：录不到请求？**
① 内置浏览器方式：确认操作的是**录制打开的那个标签页**；
② 插件方式：确认「同时录制接口请求」勾着，且页面是在**装/重载插件之后**打开的（改完插件要刷新页面），
浮层应显示 `● 录制中 · N 步 · M 接口`。
也有系统把数据渲染在前端缓存里不发请求，刷新页面再看。

**Q：插件录完，去哪勾选接口、建采集任务？**
三条路：① 停止后插件自动打开「录制结果」页；② 弹窗点「去勾选接口 → 建采集任务」；
③ 控制台首页那行的「勾选接口 → 建任务」。进去后：筛选 → 勾选 → 底部「下一步」。

**Q：删错接口了能恢复吗？**
不能。删除只作用于"这次录制结果"这个临时快照；重录一遍很快，任务与库里数据不受影响。

**Q：列表只抓到第一页 / 抓一半就停？**
看运行详情的「停止原因」：「连续两页数据完全相同」→ 改 `不分页`；「本页 N 条 < 每页 M 条」→ 每页条数填大了；
「已达最大页数」→ 调大最多页数与任务 `max_pages_cap`；什么都没有就一页 → 参数名不对，重新「自动识别分页」。

**Q：抓到一半报 HTTP 429？**
对方在限流。调大「请求最小间隔」（如 3000ms），或拆成多个任务分时段跑。

**Q：公共参数到底有没有进请求？**
看运行日志：`公共参数：query/body 3 项（tenant_id、token、page）` + 紧随的每条报文首行 URL（GET 能看到参数已在 query 里），
POST 的请求体里也能看到合并后的字段。同名参数以接口自己为准，公共参数只补缺。

**Q：登录后脚本写了但没生效？**
自检里看「参数脚本」这一步：红了就是脚本没返回可用 JSON。常见原因：
① 脚本没有 `return`（浏览器里 Eval 的返回值就是 `value`，必须 `return JSON.stringify(...)`）；
② 返回值不是 JSON 字符串；③ 站点打不开（`设置 → 内置浏览器 → 诊断`）。

**Q：落库 SQL 在哪儿看？**
运行详情日志里勾「只看 SQL」：建表 / 补列 / 建索引 / INSERT 模板 / 每批展开的整句 SQL 都在，
绿色等宽字体，可以直接复制到数据库里跑（单批最多展示 5 行，一次运行最多 60 条）。
Excel / JSON / JSONL 落库没有 SQL。

**Q：落库选 Excel / JSON，文件在哪？**
`data/harvest/<表名>.xlsx|.json`，首页与任务详情都有「产出文件（可直接下载）」卡片。
`upsert` 模式下重复跑不会让行数翻倍。

**Q：定时任务没触发？**
① 任务是否 `paused`（连续失败自动暂停）；② 看「下次触发」；③ 容器时区是否 UTC（`TZ=Asia/Shanghai`）。

**Q：入库中文变问号？**
MySQL 连接串加 `charset=utf8mb4`，库/表也用 `utf8mb4`。

**Q：`upsert` 没生效、数据翻倍？**
「去重键列」必须是真唯一键（如 `id`）；历史数据已有重复时唯一索引建不上，会自动退化为追加，先清表再跑。

**Q：字段突然多一列 / 少一列？**
多列会自动 `ALTER TABLE ADD COLUMN`；少了是这次响应没返回该字段，用「试抓预览」确认。

**Q：能不能并发抓很多接口？**
单任务串行是刻意的。需要更快请建多个任务分别设间隔，而不是把间隔调到 0。
