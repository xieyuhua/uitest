# UI 自动化录制器 · 浏览器插件（MV3）

浏览器端的**录制端**：把你手工点的每一步变成平台可回放的测试步骤，并把你自己发出的接口请求录进控制台。

三件事：

1. **UI 录制** —— 点击 / 输入 / 选择 / 勾选 / 上传 / 跳转 → 生成步骤 + 稳定元素定位；
2. **接口录制** —— 旁路记下 `fetch` / `XHR` 的请求与响应，进「接口采集 → 录制结果」；
3. **稳定 ID** —— 给每个元素写 `data-uitest-id`，页面重新打包也不失效。

服务端契约见 [../docs/API.md](../docs/API.md)；平台总体说明见 [../README.md](../README.md)。

## 1. 目录与职责

```
extension/
├── manifest.json     # MV3 清单：权限、content_scripts 顺序、service worker、popup
├── uitest-keys.js    # 共享运行时（与 runtime/uitest-keys.js 必须一致，不要单边手改）
├── content.js        # 内容脚本：监听 DOM 事件、生成步骤、浮层、转发接口录制消息
├── net-hook.js       # 页面侧网络钩子（MAIN world）：包 fetch / XHR，抓请求与响应体
├── background.js     # service worker：全部 HTTP、会话状态、导航记录、角标、接口批量上报
├── popup.html/.js/.css  # 弹窗：开始/停止、备注、开关、最近录制、接口录制
└── README.md
```

| 文件 | 负责 | 不负责 |
|---|---|---|
| `content.js` | 采集 DOM 事件、生成 Step、浮层与高亮、把网络钩子的消息转给 background | 任何网络请求、状态持久化 |
| `net-hook.js` | 主世界里包 `fetch` / `XMLHttpRequest`，记录方法/URL/状态/头/请求体/响应体（截断） | 上报（只 `postMessage`）、业务判断 |
| `background.js` | 全部 `fetch`、`chrome.storage.local["uitest_state"]`、导航步骤、角标、接口攒批上报 | 页面 DOM 操作 |
| `popup.js` | 只发消息、渲染状态、展示错误 | 直接写会话状态 |

> `uitest-keys.js` 是**共享文件**：Go 侧执行器 `go:embed` 的也是同一份逻辑（`runtime/uitest-keys.js`）。
> 改定位/动作算法请两边一起改，保持内容一致，否则"录制时能定位、回放时找不到"。

## 2. 安装

1. 打开 `edge://extensions`（Chrome 为 `chrome://extensions`）→ 右上角开「开发人员模式」；
2. 「加载解压缩的扩展」→ 选整个 `extension/` 目录；
3. 建议固定到工具栏（拼图图标 → 固定）；
4. 打开业务页面后**刷新一次**（内容脚本只在页面加载时注入）；
5. 弹窗顶部圆点应为绿色（服务端 `/api/health` 可达）；红色请先看[第 6 章](#6-常见问题)。

默认服务端 `http://127.0.0.1:8490`，改过端口在弹窗「服务端地址」里改并点「测试连接」。
服务端跑在**另一台机器**、或绑了 `0.0.0.0` 时，这里填它的局域网地址即可（例如 `http://192.168.1.23:8490`，
服务端启动日志里「局域网访问」那几行就是可用地址）。

**权限说明**

| 权限 | 用来做什么 |
|---|---|
| `storage` | 存会话状态、开关、最近录制 |
| `tabs` / `activeTab` | 记录导航步骤、打开控制台页面 |
| `scripting` | 录制标签页里补注入录制脚本与网络钩子（含 `world: 'MAIN'`） |
| `host_permissions`（`http/https` 全量） | 在被测页面注入内容脚本；请求你自己的服务端 |

## 3. UI 录制流程

1. 打开业务页面 → 点插件图标 → 弹窗顶部圆点绿色（服务端可用）；
2. 填「录制名称」→ 「开始录制」：
   - 插件 `POST /api/recordings` 建录制并记住当前标签页；
   - 页面右下角出现浮层 `● 录制中 · N 步`（开了接口录制时还会显示 `· M 接口`）。
3. 正常操作页面：点击 / 填输入框 / 选下拉 / 勾选 / 上传 / 跳转……
   - 每录到元素会闪一下 2px 靛蓝描边，浮层与工具栏角标实时增长；
   - 同一输入框连续输入只记 1 步（500ms 防抖 + 服务端合并），不会产生几十条中间态。
4. **补备注（强烈建议）**：弹窗「上一步备注」写清业务含义（如「在商品名称输入框填入测试商品名」），
   备注越清楚，执行时定位与自愈越准。
5. 需要记录回车提交时打开「回车键也记录」（默认关闭）。
6. 点「停止录制」（弹窗红按钮或页面浮层的「停止」）：
   - `PATCH /api/recordings/{id}` 置为 `draft`；
   - 进入弹窗「最近录制」（最多 10 条，点击直达控制台详情页）。
7. 到 `http://127.0.0.1:8490/#/recordings` 检查步骤、补断言、生成数据、执行。

自动记录的动作：

| 用户操作 | action |
|---|---|
| 标签页加载 / 跳转（含 SPA 路由） | `navigate` |
| 点击按钮、链接、可交互元素 | `click` |
| 文本输入（含 textarea、contenteditable） | `input` |
| 下拉选择 | `select` |
| 勾选 / 取消勾选 | `check` / `uncheck` |
| 文件选择 | `upload` |
| 回车（开关打开时） | `key` |

**不记录**：粘贴中间态（只认防抖后的最终值）、`scroll`、`mousemove`、插件自己的浮层与高亮
（`data-uitest-ignore`）、点击页面空白处（`html` / `body`）。

## 4. 接口录制

弹窗「同时录制接口请求」默认**打开**。开启后：

1. 开始录制时向服务端登记接口录制会话（`POST /api/collect/captures`，`source=extension`）；
2. 把 `net-hook.js` 注入**页面主世界**（`chrome.scripting.executeScript({world:'MAIN'})`），
   由它包一层 `fetch` / `XMLHttpRequest`，记录方法、URL、状态、请求头、请求体、
   响应体（文本/JSON，截断 256KB）；
   同时 content script 会以 `type:"Document"` 上报**页面文档**（`document.documentElement.outerHTML`，
   开始录制时一次 + 页面地址变化时一次，≤256KB），所以录制范围里的「含页面文档」在插件方式下也有效；
3. 钩子通过 `window.postMessage` 交给 content script，再由 background **攒批上报**
   （每 500ms 或满 20 条，`POST /api/collect/captures/{id}/requests`）；
4. 停止时把剩余缓冲发完并 `POST …/stop`；
5. 停止后**自动打开「录制结果」页**（弹窗里「停止录制后自动打开」可关），
   也可点 **「去勾选接口 → 建采集任务」**。

控制台里这份记录可以：按方法/类型/状态/关键字/正则筛选 → 逐条或批量删除噪声
（心跳、埋点、静态资源）→ 剩下的勾选 → 「下一步：配置采集任务」（定时 + 落库）。

| 项 | 说明 |
|---|---|
| 录的是什么 | **你自己浏览器里真实发出的**请求，登录态、插件、代理、抓包工具都不受影响 |
| 抓不到 | 二进制响应（图片/文件）、`EventSource`/`WebSocket` 流数据、页面渲染后才生成的 DOM（只上报完整 HTML 文本） |
| 什么时候抓不到 | 页面在装插件之前就打开了（刷新一次）；`chrome://`、扩展商店、PDF 无法注入 |
| 平台自己的请求 | 自动跳过 `服务端地址/api/` 与 `chrome-extension://` |
| 隐私 | 请求头/请求体/响应体原样上报到**你自己的**服务端，敏感接口请自行评估 |
| 缓冲上限 | service worker 被回收时，最多丢最后几百毫秒未上报的几条 |

关掉这个开关就只录 UI 操作、不录接口；开关状态会记住，下次开始录制生效。

## 5. 稳定 ID 原理

每个录制到的元素都会写上 `data-uitest-id="ut_xxxxxxxx"`。

1. **确定性算法**：`ut_<fnv1a32(语义指纹)>`，指纹只取
   `tag / type / 稳定 id / 稳定 name / aria-label / placeholder / label / 表单项标题 / 表格列名`
   这类业务上不太会变的信息，**不含 DOM 层级、不含随机数、不含构建产物**：

   | 会被过滤掉（每次打包都变） | 例子 |
   |---|---|
   | CSS Modules / scoped hash 类名 | `.product-card_1a2b3c`、`.css-9f8e7d`、`.sc-bdVaJa` |
   | 作用域属性 | `data-v-7ba5bd90` |
   | 组件库自动 id / name | `el-id-3812-12`、`:r1:`、`input-3`、`rc_select_7` |

   页面重新打包只要**业务语义没变**（标题、按钮文字、列名还在），key 就不变；
   同页签名相同的元素自动加 `_2/_3` 后缀去重，保证唯一且跨构建顺序一致。

2. **定位链**（按"重建后是否还可靠"排序）：
   `uid` → `attr`(`data-testid`/`data-test`/`data-cy`) → `id`/`name`（仅稳定时）
   → `label`（表单项标题）→ `near`（标题 → 同一表单项里的控件）
   → `role` / `cell` / `text` → `placeholder` → `css` → `xpath`。

3. **兜底与自愈**由 Go 执行器与共享运行时共同完成：全失败时按元素指纹打分，
   唯一最高分且 ≥5 分才认，命中后可一键写回录制。详见 [../docs/GUIDE.md 第 8 章](../docs/GUIDE.md#8-定位机制详解)。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 弹窗显示"未连接 / 服务端不可用" | 服务端没起，或端口不一致 | 起服务端；弹窗里核对地址后点「测试连接」 |
| 录制只有「打开页面」一步 | 内容脚本没注入（装插件前就打开的页面 / 系统页） | 刷新被测页，或点弹窗「注入录制脚本」，再重录 |
| 浮层不出现 / 步数不动 | 同上，页面里没有内容脚本 | 刷新页面；确认录制中且当前页就是录制标签页 |
| 「已录接口 0 条」 | 开关没开 / 页面在装插件前打开 / 页面没发 `fetch`·`XHR` | 确认「同时录制接口请求」勾着并刷新页面；换操作触发一次接口 |
| 录到的接口在控制台看不到 | 上报有最多 500ms 延迟；或服务端地址错 | 等一秒刷新；点「查看录制结果」确认会话；核对地址 |
| 换标签页后录不到东西 | 录制标签页跟着切换，旧页脚本失效 | 回到当前录制标签页操作，或停止后重开一条录制 |
| 改完插件代码不生效 | 扩展没重载 / 页面没刷新 | 扩展管理页点「重新加载」→ 刷新被测页面 |
